# Data files

## HotpotQA slice (pipeline validation only)

Used in the first stage of the project to exercise retrieval, selection, and scoring
end to end. No result reported in the paper comes from these files.

- `hotpotqa_dev_300.jsonl` — 300 HotpotQA dev questions. Each line:
  `qid` (str), `question` (str), `answer` (str), `supporting_titles` (list[str]),
  `passages` (list of `{passage_id: str, title: str, text: str}`).
- `all_passages.jsonl` — every unique passage across all 300 questions (2971 rows),
  deduplicated by `passage_id`. Each line: `passage_id` (str), `title` (str), `text` (str).

Regenerate both with:

```bash
python data/build_dataset.py
```

This downloads `hotpotqa/hotpot_qa` (`distractor` config, `validation` split) via
`datasets` and keeps the first 300 examples. The raw HotpotQA data is not
redistributed by this repository.

## Code-QA benchmark (`requests` corpus)

The benchmark behind every result in the paper.

- `code_passages.jsonl` — 320 function and class definitions extracted from the
  `requests` source tree with Python's `ast` module. Each line:
  - `passage_id` (str) — `<file path>::<definition name>`, e.g.
    `data/source_repo/src/requests/cookies.py::remove_cookie_by_name`
  - `title` (str) — `<file basename>::<definition name>`, e.g.
    `cookies.py::remove_cookie_by_name`
  - `text` (str) — the definition's source, from `ast.get_source_segment`
  - `file_path` (str) — the file the definition was taken from

  **`passage_id` is not unique.** The 320 rows carry 280 distinct IDs, because a
  definition name can repeat within one file (`auth.py::__init__` appears 6 times,
  once per class in that module). Scoring converts IDs to sets, so colliding chunks
  are indistinguishable at scoring time and `|retrieved|` can drop below `k`. See
  `results/README.md` for the effect this has on the reported precision.

- `code_questions.jsonl` — 18 hand-written questions about that source. Each line:
  `qid` (str, `q1` … `q18`), `question` (str), `gold_passage_ids` (list[str], always
  exactly one element). Because there is one gold passage per question and `k = 5`,
  per-question recall@5 is either 0 or 1.

Regenerate the passages with:

```bash
python data/build_code_dataset.py
```

This walks `data/source_repo/src/requests` and writes `code_passages.jsonl`. That
source tree is **not** checked in (`.gitignore` excludes `data/source_repo/`), so
clone the library there first:

```bash
git clone https://github.com/psf/requests data/source_repo
```

`code_questions.jsonl` is hand-written and is not regenerated by any script. Note
that re-cloning `requests` at a newer revision can change the extracted passage set
and therefore the retrieval numbers; `code_passages.jsonl` as committed is the exact
corpus the paper's results were produced from.
